# 项目团队（Project Teams）

一个项目一组**长期存在、彼此独立的 DSH Session**（PM、开发者、评审、QA）。Bot 之间直接通信，
但都不是任何 Agent 的子代理，也不继承其他 Bot 的对话历史。

## 这一版做了什么

- **独立会话绑定**：Bot 会话由宿主通过 `ctx.sessionController.create` 创建为普通会话
  （无 `parentSessionId`、无 subagent origin），并以 Bot 实例持久保存 `session_id`；重启后仍然指向原会话。
- **宿主 API + 工作台界面**：项目、团队、任务、消息、交付、审批全部保存在宿主侧 SQLite；页面只通过插件
  自己的 HTTP API 读写，不在浏览器里维护权威状态。
- **确定性任务引擎**：状态机、依赖 DAG 校验、原子认领、租约、版本乐观锁、预算与重试上限都在程序内执行；
  模型文字不改变任何状态。
- **隔离工程执行**：每个写入型任务运行拥有独立的 `git worktree` 与分支，位于仓库内
  `.project-teams/runs/<run>/worktree`（该目录通过 `.git/info/exclude` 从你的变更里排除）。
  提交、Diff、测试日志作为可复核工件保存。
- **独立评审与门禁**：评审者使用独立会话与最小上下文，只读；build/test/secret 扫描证据来自真实命令退出码；
  新 commit 会使旧评审与旧证据失效；高风险动作只能由人类 Owner 在「决策」页批准，且批准绑定到确切 commit。

## 使用方式

1. 安装后，左侧栏选择 **项目团队**（或在 设置 → 插件 → 项目团队 打开）。
2. 新建项目，选择本地 Git 仓库目录（至少一个 commit），填写策略检查。
3. 点击 **生成 4 个 Bot**：宿主为 PM / 开发者 / 评审 / QA 各创建一个独立 Session 并写入绑定。
4. 在「任务」页提交带验收标准的需求，分配给开发者 Bot。
5. 开发者在独立工作树里开发并提交工件、运行检查、请求评审；评审者在独立会话里盲审。
6. 门禁只有在「真实机器证据 + 独立评审 + 必要的人类批准」同时满足时才会通过。

## 权限与限制

- 单机、单用户（P0）。多人 RBAC、云端沙箱与远程流水线属于 P2。
- 工作树隔离只防写入冲突，不替代操作系统级沙箱。
- 评审结论不能替代确定性检查；模型仍可能受提示注入影响，因此 ACL、审批与完成判定都在宿主代码里执行。
- 批准、暂停、归档、修改策略只能由你在界面完成，模型无法代为执行。
